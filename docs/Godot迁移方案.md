## 需要重新实现的部分

1. **战斗结算。** 把 `combat.js`、`mana-cycles.js`、`multi-enemy.js`、`shields.js`、`action-points.js` 等模块拆成纯规则服务。输入是战斗状态和玩家行动，输出是下一状态及事件列表。属性加减、多段伤害、控制检定、资源回转、护盾期限、BOSS 连招都在这里处理。
2. **界面。** `interface.js`、技能悬浮框和 CSS 布局改为 `Control` 场景。三人队伍各四个技能位；资源颜色、BUFF 第一位特殊资源、强化星标、AP 格子等使用本轮定稿。底栏按可用高度分档，至少核对 1280×720、1920×1080 和宽屏，避免战场再次被挤扁。尺寸与锚点用于适配不同窗口。[官方界面布局说明](https://docs.godotengine.org/en/stable/tutorials/ui/size_and_anchors.html)
3. **战斗表现。** 保留现有 `battle-feedback.js` / `scene-feedback.js` 的事件结构和受击时点，改用 Godot 动画、粒子和镜头。实际生命下降才触发受击动作；护盾吸收只播放吸收反馈。动画不回写战斗数值，防止重播动作造成重复伤害。
4. **场景效果。** Three.js 的水面渐隐、自定义材质、粒子、发光与程序动画要重建。首轮保留主题、颜色与作用，控制效果数量；灯光与材质导入后需要实机比对，不能承诺与浏览器完全一致。
5. **音频。** 27 首 BGM 和配音直接导入。用独立的音乐、音效、语音总线管理音量，两个音乐播放器完成交叉淡入淡出。保留魔晶核心暴露后返回常态曲、最终放电后回退等规则。MP3 可直接导入，不需要重新调用生成 API。[官方音频导入说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_audio_samples.html)
6. **存档。** 浏览器本地存储改为 Godot 的 `user://` 文件。沿用角色、技能、奖励和关卡 ID，使用明确版本号。网页版增加一次性导出，Godot 增加导入与校验；新运行时的旧存档应通过迁移函数处理。正式招募进度和 GM 临时全开继续分开记录。[官方存档示例](https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html)

## 实施顺序

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 1. 固定当前规则 | 本轮玩法定稿、最终生效的数据表、可重放的行动样例 | 四技能配装、属性变化和控制检定都有确定预期；不能只截取被后续覆盖的旧技能定义 |
| 2. 一场完整战斗 | 一个场景、魔晶巨人、尼布斯/艾佩莉雅/雷克，哈特作为可替换角色 | 覆盖四类资源；能选技能和目标、敌人出手、破韧、开核、胜负结算、重开 |
| 3. 校验数值与表现 | 规则移植、技能与 BUFF 界面、动画及声音同步 | 同样初始状态和行动序列得到相同伤害、资源、属性和事件；控制随机数使用相同种子或固定检定输入 |
| 4. 扩展完整远征 | 教学、招募、配装、三选一奖励、多敌人战斗、分支与最终结局 | 从单人教学开始打完一条路线；未招募角色不会进入奖励池；替补和技能顺序正确保存 |
| 5. 完善场景与发布 | 间章行走互动、全部模型、音频切换、设置、桌面导出 | 所有 5 个环境和 10 位正式 BOSS 均能加载，存档可恢复，窗口缩放正常，完整流程没有资源缺失 |

第一阶段的测试样例应包括：同一属性变化对多段每一击生效；减益到期还原；控制抵抗成功与失败；强控结束和后续抗控；单体与 AOE；低血量触发游墓形态及属性切换；小份兑现与大份兑现的回魔差异；两轮护盾；魔晶核心与最终 BOSS 的失败回退。网页现有测试可提供预期结果，但 Node 测试脚本本身不能直接当作 Godot 测试运行。

## 建议的工程结构

在独立目录建设 Godot 项目，保留网页版作为数值与表现对照。以下目录仅是建议，本次未创建。

```text
grande-godot/
  project.godot
  assets/                模型、立绘、环境、音频
  data/                  角色、技能、敌人、剧情、奖励、音频索引
  rules/                 战斗状态、属性、控制、资源、敌人连招
  scenes/battle/         战场、角色与敌人实例
  scenes/ui/             技能卡、BUFF、预告、对话、整备
  scenes/exploration/    间章行走和互动
  services/              存档、音频、流程切换
  tests/                 固定行动序列与迁移校验
```

BOSS 头顶信息继续采用屏幕空间界面，把三维锚点投影到屏幕，并处理遮挡、屏幕边缘和相邻框体碰撞。这样字体保持清晰，也能继续使用完整悬浮框。战斗中先沿用固定站位与动作位移；间章再增加真实碰撞和行走。等单场战斗验收后，逐步替换角色的程序动作和模型细节。

本次已经具备迁移所需的引擎与大部分静态资产。实际工作量主要集中在规则移植、界面重建和流程对齐，建议以“先完成一场能玩的战斗”为首个交付点。
