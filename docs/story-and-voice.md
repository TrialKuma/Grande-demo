# 《停机之前》剧情与离线中文配音

这次更新完整重写六章战前、战后对话，新增旁白，共 263 句、9697 个字符。角色沿用原设；学院考察、旧设施事故、学生林晏、值班员及本次救援是 demo 原创支线，不把它们当作原角色卡已有的经历。

## 故事如何展开

| 章节 | 这次要做什么 | 战后发生什么 |
| --- | --- | --- |

“七名考察队员”与“七位同行角色”是不同的人。补丁 Z 原本独自查档，被困在相邻存档间，不在考察队的七人名单中。游墓是游木体内的另一个人格，不增加上阵人数。加入的同伴始终参与旅途中对话；每场战斗只从当前同行角色中安排三人上阵。

## 人物的写法与原设依据

- **尼布斯拉姆**：原卡《尼布斯拉姆（Knibbs-rhaam）》B15–B17 的豪爽、好奇和工会经历。他愿意下去，因为工会救援队已经受伤；好奇仍在，但在救援途中会安排路线、撤离和分工，不每句都喊口号。
- **艾佩莉雅**：原卡《人设》B15–B20 的嘴欠、信息能力与监视雷克的任务。对熟人讽刺，对伤员和学生则直接提供帮助。紧急阶段不把每句话都写成笑话，也不把她写成只汇报系统状态的机器。
- **雷克老板**：原卡《雷克老板（Master Ric）》B15–B20 的圆滑、古怪、知识积累和尼布斯的长期关系。他能判断旧锁与危险，也会做实际善后；不会靠连续卖关子或金钱笑话表现神秘。
- **哈特蒙斯**：原卡《哈特蒙斯（Haart-Monns）》B7、B15–B18 的学院身份、心智领域、怕麻烦与兄弟关系。这里让他承担持续联系学生、承认疲劳、事后查责的责任，而不把心理安抚误写成可以代替外科止血的万能医疗。
- **潜行**：原卡《潜行》的人物说明与《升格模组》银焱条目。冷静、求知、有自己的前哨目标；说明工程事实时尽量说对同行决策有用的信息。银焱爱看漫画只出现在暂时缓和的一处，不盖过险情。
- **游木／游墓**：原卡《Sheet1》B14–B19、H14 的认真医生与标本爱好者船长。医生对伤员提出具体、可执行的照料要求；船长有经验、会与他争嘴，也会在需要时合作，不只是逢人索取标本的噱头。正文为虚构救援场景，不作为现实急救教程。
- **补丁 Z**：原卡《补丁Z》B15–B19 的侦探、秘法商人、逻辑漏洞敏感与历史资料调查任务。以核对编号、签名和记录解释他为什么能推动故事，而不是每句都使用计算机术语。声称“全是零件”的台词也有原卡背景依据。

原始目录为 `Ric-Others/角色设定等13个文件/角色设定/`。没有修改这些工作簿。战斗能力的具体改写另见角色设计说明，剧情不额外引入第五类施法资源。

## 配音资产

每一句台词、旁白都有一段已经生成好的中文 MP3。新版通过在线神经语音生成素材；运行游戏时只播放本地文件，不调用浏览器临时朗读，也不访问网络 TTS。独立 HTML 内嵌这些音频，游玩时不需要语音服务账户或密钥。

- 清单：`public/voices/manifest.json`
- 共 263 段，总时长 2210.76 秒（约 36 分 51 秒），文件总量 13,264,560 字节（约 12.65 MiB）；每条时长与大小都记录在 manifest 中，可直接求和核验。
- 格式：MP3，单声道，24,000 Hz，48 kbps。
- 生成：通过 **edge-tts 7.2.8 第三方客户端**使用 Microsoft Edge Read Aloud 在线神经声库。它不是微软官方 SDK，也不是本地运行的语音模型。[项目说明](https://github.com/rany2/edge-tts)
- 这次实际读取服务声库得到 322 种声音，其中中文相关声音 14 种；选用 **7 种独立神经基础声线，其中 5 种为男声**，替换此前的 Windows 桌面语音。完整参与选角的实时声库记录放在 manifest 的 `voiceCatalog` 中。
- 六种大陆普通话声音各生成两句比较样片，并另外验证了台湾普通话的 YunJhe。均正常生成可解析 MP3。模型在本会话不支持听取音频输入，因此没有把技术验证说成已完成主观听辨；音色是否符合预期应通过游戏内试听判断。
- 神经声线仍是合成配音，不是真人演员。此客户端只开放声线、语速、音量、音高等设置，不支持任意情绪 SSML，所以不会承诺精确的愤怒、嘲讽或慵懒表演。[客户端功能边界](https://github.com/rany2/edge-tts#custom-ssml)

正式预设位于 `scripts/neural-voice-profiles.json`，每个人都记录了原设对应的选角理由。并非所有角色都拥有独占声线：雷克、哈特蒙斯与游木，尼布斯与游墓等共享基础声音，但医生与船长使用不同基础声音；没有再让绝大多数男性共用一个康康声线。哈特蒙斯经反馈换掉偏幼的 Yunxia，采用成年青年男声基础；音高只轻微降低，避免变成低沉大叔。试听片段选用他嫌同伴多管闲事的对白。懒散与小脾气是选角方向，当前合成接口不能单独指定精细表演情绪。

清单接口：

```js
{
  version: 1,
  clips: [
    { key, speaker, text, src: '/voices/<text-hash>-<voice-hash>.mp3', duration, voice, rate, pitch, voiceHash, bytes, sampleRate, bitrate, audioSha256 }
  ]
}
```

`key` 是 `speaker + '\n' + text` 的 SHA-256 前 20 位。`voiceHash` 是 `voice + '\n' + rate + '\n' + pitch` 的 SHA-256 前 8 位。文件名同时包含两者，改字幕或选声配置都会改变 URL，避免浏览器继续命中旧音色缓存。播放端仍可直接通过 `speaker + text` 匹配；改台词后必须重新生成对应音频，不能保留旧字幕去播放新句子或反过来。

## 如何复现生成

1. 在独立的 Python 构建环境安装 `edge-tts` 与 `mutagen`；不加入游戏运行依赖，不读取用户的服务密钥或浏览器凭证。
2. 根据实际声库核对 `scripts/neural-voice-profiles.json`。声音供应可能变化，不能用 Azure 完整声库推断 Edge 免费接口一定支持某个声线。
3. 在游戏目录先预览本次需要生成的句数。此步骤不联网、不写文件：

```text
python scripts/generate-neural-voices.py --dry-run
```

4. 执行生成。默认复用已通过校验的音频，仅新增或变化的句子需要联网生成：

```text
python scripts/generate-neural-voices.py --concurrency 3
```

脚本通过 Node 读取 `src/story.js`，先报告复用、新生成和移除的句数，以及需要重配的角色。没有待生成句子时不访问在线声库；台词、选声配置和清单均未变化时直接结束，音频与清单都不重写。`--incremental` 保留兼容，已经无需手动添加；只有明确使用 `--full` 才会要求全部重配，也可以先用 `--full --dry-run` 预览。

| 修改内容 | 配音处理 |
| --- | --- |
| 新增 BOSS、技能或修改数值，未动对白 | 不生成音频 |
| 新增对白 | 只生成新增的句子；同角色说完全相同的文本可复用 |
| 修改一句台词 | 只重配这一句 |
| 调整对白顺序或章节位置 | 复用音频，按需更新清单 |
| 删除对白 | 不生成音频；移除不再引用的旧清单托管文件 |
| 更换某角色的声音、语速或音高 | 只重配该角色使用这一配置的台词 |
| 修改选角理由等说明文字 | 更新清单，复用音频 |
| 重新构建网页或独立 HTML | 打包已有 MP3，不调用配音服务 |

例如把“四面破镜”改成“悬浮的破镜”时，只重新生成了该句旁白，另外 262 句保持不变。已有音频会核验格式、大小及选声设置；有 `audioSha256` 时还会核验内容摘要，损坏或丢失的文件只让对应句子失效。旧清单缺少摘要时兼容原有校验，在下一次实际更新清单时补齐，不为迁移而重写整套素材。

确需生成时才获取真实在线声库。并发限制为 1–4，默认 3；暂时失败最多尝试三次，访问拒绝则停止。全部待生成句子成功且格式校验通过后，先把旧清单和相关素材备份到系统临时目录，再发布文件并原子替换 manifest。清单提交成功后才清理不再引用的旧文件；手动放入、未列在旧清单中的 MP3 保留。生成失败不会覆盖正式素材；清单提交失败会回滚本次安装的音频。

构建流程的离线回归检查（在同一 Python 构建环境执行，不调用配音服务）：

```text
python -m unittest discover -s tests -p "voice_generation_test.py" -v
```

旧的 `generate-voices.mjs/.ps1` 留作此前桌面配音的构建记录，不再作为当前生成入口。

素材检查包括每句字幕与 hash 的一一对应、MP3 文件大小、MPEG 版本／声道／采样率／码率和选角元数据。浏览器播放控制、音频解码和独立 HTML 的嵌入校验由集成流程另行验证；仅生成这些文件不代表已经完成主观实听。
